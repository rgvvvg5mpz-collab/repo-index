fiduciary-judge-v01PrivateIn progress

Python · created 31 Oct 2026 · local copy: this folder (Fiduciary Model) · last push 2 Nov 2026

A small model that acts as a fiduciary judge, or guardrail, for an AI advice chatbot. For each bot reply, given the conversation, the client's profile and the firm's product shelf, it decides whether the reply meets the best-interest or fiduciary standard (Reg BI, or the Advisers Act and IA-5248). It also names the duty that fails, with the rule cite and the evidence, and picks an action: approve, revise, gather information, block or escalate.

State: In progress. README says "in design". The v01 dataset is built (about 35k conversations) and the pass/fail screens are trained and released (screens-v01). Next step: train the Phi-4-mini judge, v02.

Contains
  • src/fiduciary/: taxonomy (7 duties, 29 categories, 129 subtypes), scenario sampler, schema and checker, chunk writer, source-refresh crawler
  • data/: raw regulatory sources, pilot and v01 chunks, agent outputs, and build_v01 (about 35k conversations)
  • Models/: Phi-4-mini judge, plus Qwen3-0.6B and Ettin-1B pass/fail screens, with an AWS infrastructure comparison
  • docs/: TAXONOMY, DATA_PLAN, SOURCES_TO_MINE, exec deck
Results
Pass/fail screens: test fail recall 99.3% (Qwen3) and 99.2% (Ettin), out-of-distribution 98.7% and 98.5%
Builds on
FINRA2210_correspondence (recipe) and RegModels (Reg BI detector)

FINRA2210_correspondencePrivateCompleted

Python · created 17 Oct 2026 · release v0.1.0 · last push 18 Oct 2026

A Phi-4-mini (3.8B) LoRA fine-tune that does a first-pass compliance review of broker-dealer communications under FINRA Rule 2210: emails, texts, social posts, web pages, seminar scripts and more. For each message it gives the communication type, whether it complies, each violation with its rule paragraph and the offending words, severity, and the next step for the reviewer.

State: Completed. Model and dataset released as v0.1.0. The planned chat top-up hasn't been built.

Contains
  • src/finra2210/: taxonomy, scenario sampler, checker, prompts, training, evaluation
  • data/: 11,896 in-domain and 5,800 out-of-distribution synthetic labelled communications
  • training/ (mlx-lm and NVIDIA), evaluation/ (confusion-matrix dashboard), results/
  • retraining/: rule watch, feedback, label audit, SFT, DPO, GRPO, release gate
  • MODEL_CARD, Marketing/ (13-slide deck, 3-minute video)
Results
Compliant/not compliant correct 96.5% on test and 95.3% out of distribution; violation detection F1 0.97 and 0.96

An end-to-end system for regulatory surveillance of client-facing GenAI chat. It has six small, auditable models, one per rule regime, and a reference chatbot that screens every turn through them, with a loop for subject-matter-expert (SME) review.

  • RLHF_RLAIF_UI/: SME review console, LLM judge, threshold bandit, gated retraining
Results
Test macro-F1 0.966–0.995 across the six models, and every regulatory recall floor is met

claspPrivateCompleted

Python · created 6 Oct 2026 · last push 11 Oct 2026

CLASP (Contrastive Labelling And System-1 Prediction) is a workbench for fast text classifiers. They are small contrastive heads (CLM-8B) on a frozen Qwen3-8B encoder. Its browser UI covers the whole loop: data curation with Claude Code, training, chat and flagging, and post-training with a promotion gate. The worked example is a 5- or 7-way securities-regulation regime screener built on RegModels data.

State: Completed. Models v1.0 and v1.1 released, along with the demo video.

Contains
  • app/: FastAPI workbench, training jobs and model registry, Claude Code runner, static UI
  • engine/: encoder, embedding store, contrastive head trainer, classifier
  • examples/regulatory/, model_validation/, Tests/ (dated evaluation runs)
  • docs/: architecture, developer guide, methodology; a 9½-minute demo video in the releases
Results
Held-out macro-F1 0.983 (5-way) and 0.977 (7-way)

clm-nemotronPublicCompleted

Python · created 18 Oct 2026 · fork of Contrastive-LM/CLM · last push 18 Oct 2026

Fast, cheap, private text classification on NVIDIA Nemotron embeddings. A small model on top of a frozen encoder learns your labels from your examples, and you can train it in a browser. It answers yes/no, pick-one and scale questions about a text in tens of milliseconds on a laptop.

State: Completed. Models released (models-v1); tests run in CI on every push.

Contains
  • src/clm/: clm-serve (API and playground), clm-train, clm-encoder, clm-benchmark
  • docs/ (user guide, training, API), Crew Training/ (video, exercises)
  • Marketing/ (deck, video, frontier benchmark), Model Governance/ (model cards, lineage, risks)
  • Claude Code/: setup, start and stop scripts; tests/ runs in CI
Results
88–96% accuracy on support-ticket routing from 300 examples, 33 ms median latency, about $8 per million decisions (demo figures)

language-model-selectionPrivateCompleted

Python · created 22 Aug 2026 · last push 30 Aug 2026

Point it at an application and it finds every language-model call, works out what each one is for, and ranks the ways to run it against a cost, latency and accuracy objective you set. Options include Anthropic, Gemini, the Bedrock catalogue, hosted open weights and self-hosted GPUs. It also advises whether a job should be a single call, a workflow or agents. You can use it as a service, a UI with sliders, or a CLI.

State: Completed. README says "working end to end". The quality and latency figures are still default estimates, not measurements.

Contains
  • src/lms/: pure-stdlib engine (scan, recommend, refresh)
  • configs/: a catalogue of 34 models, plus measurements to replace the default priors
  • static/ (UI), examples/sample_app/, .claude/skills/
  • docs/: exec one-pager, manual, methodology

PromptOptimizerPrivateCompleted

Python · created 26 Aug 2026 · local copy: PromptOptimizer 1.0 · last push 2 Sep 2026

Middleware that keeps an application's behaviour stable when you switch its LLM from model A to model B (Anthropic, Bedrock, Gemini, OpenAI-compatible). At design time it measures drift with a Behavioral Similarity Index and adapts the prompt until it passes an equivalence gate. At runtime it serves the adapted prompt with a p99 of about 1 µs.

State: Completed. v1.0.0 released.

Contains
  • src/promptopt/: lint, baseline, candidate generation, BSI scoring, gate, runtime adapter, provider adapters
  • configs/promptopt.yaml, examples/, scripts/ (embedding setup), tests/
  • docs/: user manual, methodology, design, router; 1-pager and architecture HTML

A research harness for a "house-money ladder" strategy. You stake X and try to double it within a month, take the stake out on the first double, and then raise the risk using the profits, guided by a four-layer signal model (macro, geopolitics, sector, company). State: In progress. The engine runs. Calibrating it needs a market-data source, which hasn't been connected.
